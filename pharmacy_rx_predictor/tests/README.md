# テスト / 動作確認

ネットワークに一切アクセスせずに、ツールのデータ収集部分を検証します。
ナビィを模したフェイクサーバ（`fakenavii.py`）を相手に、各ツールの収集処理を
最後まで走らせて「取りこぼしが起きていないか」を確認します。

```bash
pip install beautifulsoup4 requests        # streamlit等は不要
python3 tests/test_parsers.py              # パーサ単体（新旧HTML両対応・重複排除など）
python3 tests/test_e2e.py                  # 3ツールの収集処理を通しで検証
```

## なぜ必要か

2026年7月にナビィの検索結果ページで施設名の見出しが `<h3 class="name">` から
`<h2 class="name">` に変わり、`pharmacy_area_finder.py` と `area_analysis.py` が
**「検索は成功するのに常に0件」** になりました。検索リクエスト自体はエラーに
ならないため、画面上は「動いているが何も出ない」という分かりにくい壊れ方をします。

`test_e2e.py` は「ナビィが医療機関57件・薬局34件を返す」状況を作り、ツールが
それを1件も落とさずに取得できるかを確認します。同じ壊れ方をすれば即座に落ちます。

## 何を検証しているか

| 観点 | 内容 |
|---|---|
| HTML変更耐性 | 施設名の見出しが h2 / h3 のどちらでもパースできる |
| ページング | 総件数を正しく読み、3ページ目まで取りに行く（打ち切らない） |
| 総件数の誤読 | 「20件表示」を総件数と誤読しない |
| 重複排除 | 「田中内科」と「中田内科」、同一チェーンの別店舗を消さない |
| 座標 | 全施設の座標が確定し、門前/面の判定まで到達する |
| 詳細取得 | 年間処方箋数・1日外来患者数を全件取得できる |

## ファイル

| ファイル | 役割 |
|---|---|
| `fakenavii.py` | ナビィを模したフェイクHTTPセッション（任意件数の施設を返す） |
| `fixtures.py`  | 一覧ページの模擬HTML（旧 h3 版 / 現行 h2 版の両方） |
| `loader.py`    | Streamlitアプリのロジック部分だけをUIを描画せず読み込む |
| `stubs.py`     | streamlit / folium / pandas 等のスタブ |

## 実際のナビィ側が変わったかを見る

ツールが再び0件になった場合は、まずリポジトリ直下の構造チェッカーを実行して
ください（こちらは実際にナビィへアクセスします）。

```bash
python3 navii_health_check.py
```

どの前提が崩れたか（結果カード・見出しタグ・詳細リンク・総件数の読み取り）を
1項目ずつ表示するので、修正すべきパーサがすぐ分かります。
